    Release Notes & Changelog

    All notable changes to this project will be documented in this file.

    The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

    [Unreleased]

    Added

    • Estimate real release downloads without telemetry: scripts/release_stats.py subtracts each release's floor of automated downloads (its least downloaded SBOM) from its package counts, and a weekly workflow records the estimate, stars, and daily views and clones on the stats branch. The README shows them with the star history.

    Fixed

    • ttp start and ttp restart exited with 0 when Tor, or a pluggable transport the bridges need, was not installed. No session existed, and under restart the previous one was already gone, so a script that trusted 0 ran in cleartext. They now exit with 1, which is what the 0.5.0 exit code contract says for an operation failure. Nothing is installed, as before.
    • ttp logs without sudo crashed with a PermissionError traceback, and ttp check-leak and ttp watchdog status reported an unreadable session as inactive. All three now say that root is needed and exit with 1.
    • ttp config --help had no description, and ttp restart --help none for --notifications and --notification-user.
    • ttp status run without sudo after any session said "Cannot read the session intent": /run/ttp stays root-only (0750) until reboot. It now says the state is readable only by root and to run it with sudo, and the docs show sudo ttp status and sudo ttp check.

    Documentation

    • The CLI reference covers 0.5.0: monitor, config, status --json, the notification and VPN options, what restart refuses, and every exit code from 0 to 10 with what it means for the network. The automation tutorial branches on all of them instead of treating every nonzero code as cleartext.
    • The watchdog explanation describes the 0.5.0 supervisor (systemd readiness and WatchdogSec, the termination hook, the AppArmor and VPN checks, the latched and verified emergency) instead of the 0.4 state machine.
    • docs/interfaces.md no longer says that start installs Tor, and lists the missing commands and options. The operator guide's exit table includes 10.

    Tests

    • The round-trip bypass test runs its echo server in a host namespace of its own (NSE 2.3.0, isolated_host=True), so the host's firewall no longer sits between the sandbox and the server. On Fedora, firewalld's default zone dropped the request and the test reported a one-way bypass, or asked for a firewall-cmd --zone=trusted workaround, for something TTP had not done. The nse extra now requires network-sandbox-engine>=2.3.0.
    • Unit tests no longer read the host's /run/ttp. On a machine that had run a real session, 44 of them failed with PermissionError. An autouse fixture points every module-level runtime path at an empty directory, and a guard test fails if any module still holds a /run/ttp path it does not redirect.

    [0.5.0] - 2026-11-21

    Reported state now matches the evidence behind it. ttp status, ttp check and the new ttp monitor say what was observed and when, a required watchdog must prove it is evaluating before ttp start succeeds, and its emergency containment holds until ttp stop. New and optional: a VPN before Tor (--require-vpn, a native NetworkManager WireGuard tunnel) and desktop notifications. On AppArmor kernels, Tor must run confined in enforce mode. Qualification found and fixed five defects, among them onion-address traffic leaving directly under LAN bypass, and cleartext FIN/RST packets after ttp stop.

    Upgrade notes: Python 3.12 is now the minimum (0.4.11 remains available for 3.10 and 3.11). Fedora 45 has its own signed .fc45.noarch.rpm; read the verification guide before importing its key. Exit codes 5–9 are new and are listed in the session observations guide.

    Added

    • Document the post-0.5.0 leak-testing and hardening plan, with scenario matrices, evidence gaps, positive/mutation controls, continuous fault observation and release acceptance criteria. Prioritize core hardening before application isolation; retain existing 0.5.0 VPN qualification gates.
    • Add disposable QEMU VPN qualification with real Tor/DNS, an external packet observer, DHCP renewal and persistent containment across tunnel reconnection.
    • Qualify the required VPN mode across six IPv4/IPv6/dual-stack underlay, endpoint and tunnel topologies, a private obfs4 bridge, suspend/resume and reboot. The observer accepts only the guard's IPv6 control exceptions; peer counters detect cleartext application traffic entering the tunnel; a continuous probe covers sleep and the whole shutdown. Resume latches emergency by design and requires a new session. Run each gate as its own CI job.
    • Add required VPN-before-Tor mode for an active native NetworkManager WireGuard profile, with mandatory watchdog, frozen path identity, a kernel guard before Tor startup and explicit recovery. Reject bypass/restart and retain emergency across reconnects. See the VPN guide for the restricted scope and the VM qualification results, including ParrotOS.
    • Add ttp monitor: a passive, root-only terminal view of existing session evidence with a short in-memory timeline of changes seen while open. It does not run Tor/DNS probes or modify the session; Ctrl-C leaves TTP running.
    • Build a separate Fedora 45 RPM with its Python 3.15 ABI, sign it with a fresh OpenPGP key for each release, and publish the public key and Sigstore bundles. Keep the Fedora 44 RPM and its existing Sigstore distribution path.
    • Rehearse Fedora 45 signature verification and installation in CI, and check published signed package contents against an unsigned rebuild of the tag.
    • Reviewed Python dependency locks with artifact hashes for source installation, CI and documentation, plus a separate newest-dependency compatibility job.

    • Production parser properties shared by Hypothesis and ClusterFuzzLite/Atheris. Main now requires PRs; the administrator bypass is restricted to PRs, with no mandatory independent reviewer for the single-maintainer workflow.

    • Required watchdog readiness and useful-progress evidence, frozen configurable deadlines, suspend-aware freshness and an independent systemd termination handler. Emergency mode survives watchdog restarts until explicit stop.

    • Optional desktop notifications with an unprivileged recipient agent, authenticated Unix IPC, bounded D-Bus calls and acceptance receipts. Delivery failure is reported separately and never isolates traffic by itself.
    • ttp config [--session], ttp status --json, independent watchdog/notification flags and diagnostic codes 5–9, with all concurrent causes retained. See session observations and ADR 0013.

    Changed

    • Declare Python 3.12 as the minimum in the Debian, RPM and Arch package dependencies, and check it before source installation changes system files.
    • Raise the minimum supported Python version to 3.12. Python 3.10 and 3.11 remain supported by the published 0.4.11 artifacts, but are no longer in the development CI matrix or dependency locks.

    Fixed

    • ttp check no longer latches emergency containment on a healthy session by sampling the required watchdog mid-evaluation. A live watchdog reports itself as evaluating during each periodic check and after each nftables or DNS-file event; one sample in that window counted as "no operational evidence" (2 of ~56 CI VPN VM runs, whose watchdog then reported the emergency table as a firewall integrity failure). check and watchdog startup now wait for the supervisor's next completed observation, bounded by its own deadline (25 s by default); stopped, stale or foreign evidence still contains at once.
    • Close every TCP connection redirected to Tor before ttp stop removes its rules. An orphaned socket backing off between retransmissions could survive the fixed 300 ms reject window and, once the rules were gone, send its FIN in cleartext to the destination an application tried during the session; Tor's orphaned TransPort end kept the host answering with RSTs that left the physical link with a stale ::1 destination (IPv6, seen by the VPN VM's external capture). Stop now destroys both ends of each connection with SOCK_DESTROY, verifies they are gone, and otherwise exits 8 keeping rules, DNS and lock. Connections come from conntrack and from the kernel socket table, because conntrack forgets a closing connection within seconds while Tor's orphaned end in LAST-ACK keeps retransmitting for minutes (21 RSTs to ::1 in a dual-stack VM run). No conntrack or ss binary is required.

    • Reserve Tor's virtual destinations before LAN bypass, redirecting synthetic TCP and rejecting unredirected traffic. Narrow IPv6 automapping to fc00::/8 so ordinary fd00::/8 LANs remain available. Add a real-onion dual-stack VM gate with reused mappings, external captures, pre/post controls and targeted rule-removal regression, plus NSE checks and documented compatibility limits.

    • Continuously observe TCP, UDP and DNS during chaos injections instead of inferring containment from recovery audits after an 18-second wait. Retain calibrated full captures and separate privileged enforcement exposure from recovery, with missing evidence and persistent hold leaks failing the gate.

    • Regenerate the full runtime dependency closure for Typer 0.29.1, including its Pydantic dependencies, and refresh filelock. Validate a clean locked runtime and CLI in CI so development dependencies cannot hide missing pins.
    • Resolve related Dependabot updates together, retain the oldest supported dependency pins, and refresh CI/docs locks and pinned GitHub Actions. Pass the offline WireGuard fixture's ephemeral peer key through stdin rather than a file path denied by some namespace-entry confinement policies.
    • Require calibrated external packet evidence for DNS/UDP leak-test verdicts; socket errors, DNS error replies and aggregate counters no longer certify containment. Preserve per-flow captures and fail incomplete observations.
    • Check the required VPN's final egress device after transparent rerouting, avoiding blocked local Tor connections while retaining the same fail-closed transport restrictions. Add a real-packet regression with the old hook mutation.

    • Keep the audit tool on Python 3.11+ with patched filelock, avoiding its vulnerable Python 3.10 fallback in the CI lock. Audit every locked version regardless of Python/platform markers, and make oldest-dependency inputs self-contained for Dependabot.

    • Resolve integration STUN targets before enabling TTP, separating the UDP containment probe from exit-dependent AAAA resolution. Missing targets still fail loudly rather than being reported as containment.

    • Allow systemd generator mount setup in the disposable offline CI container on AppArmor hosts, and attach its console so early boot failures are visible.

    • Run Fedora integration against pinned Fedora 44: the old Fedora 41 Tor cannot negotiate protocols required by the public network. Wait for systemd boot in the offline session fixture, provide its required core limit explicitly, and preserve container diagnostics on failure.

    • Preserve CLI compatibility with the oldest supported Typer version and isolate configuration ownership fixtures from pytest capture and the runner user.

    • Treat unavailable external verification as inconclusive (code 3), with no claim of isolation. A valid negative from a non-exempt probe requests containment; requested, applied and independently verified remain distinct.

    • Replace the entire TTP table atomically, including chain declarations, so emergency repair handles altered hooks/types. No flush-only hash is trusted as an emergency specification.
    • Preserve explicit stop intent after lock removal, including restore-only with corrupt/missing intent. Late observations cannot overwrite another session.

    • check-leak no longer labels unavailable DNS observations as detected leaks.

    • Keep installed Python code and generated DNS configuration accessible under restrictive administrator umasks (0027, 0077), without widening access to TTP's private runtime state. Existing source installations are repaired on reinstall.

    • Temporarily disable inherited global DNSSEC validation while using Tor's DNSPort, restoring the previous configuration at teardown. Explicit per-link DNSSEC=yes is preserved and refuses start/restart before network changes, with a visible explanation, documentation link and dedicated exit code 4. An inconclusive policy inspection returns a separate generic error (1).
    • Use nft delete table for teardown compatibility with nftables 1.0.6, retaining the existing absent-table handling. The real NSE teardown test also verifies that repeating cleanup succeeds.
    • Use numeric output NAT priority -100 in the Docker-shaped NSE fixture; nftables 1.0.6 rejects dstnat in that hook.

    Tests

    • The bypass round-trip test first makes the same round trip without TTP's ruleset, so a host firewall that drops the echo (firewalld's default zone on Fedora does) fails it as a harness problem instead of blaming TTP's bypass.
    • Require network-sandbox-engine 2.2.0 for the zero-leak suite. Its captures return from start() only once the kernel socket is bound and filtering, so the fixed 0.2 s sleep after it is gone (NSE measured 2.1.2 without the sleep missing about one stimulus in 25). Every capture now also fails when its report says the window was incomplete (kernel drops or limits), and the gateway listener confirms its bind instead of a fixed 0.5 s wait.
    • Cover monitor incident transitions, stale historical evidence, failed observations, terminal control sanitization and non-mutating exit signals.

    • Add isolated real systemd/nftables tests for SIGSTOP/SIGKILL, independent containment, restart latching, tamper repair and explicit stop. Private D-Bus tests cover unprivileged delivery, ordinary and critical expiry, deduplication, replacement, server failure and an ambiguous timeout after receipt.

    • Cover restrictive-umask DNS creation/restoration, installation access, inherited versus explicit DNSSEC policy, inspection failures and preflight refusal before any network mutation, including restart and quiet mode.

    • Verify the policy adapter with real systemd-resolved and systemd-networkd on Debian 13 and Fedora 44 in isolated, network-disabled containers, also in CI.
    • Exercise the systemd-resolved UID restriction with NSE on IPv4 and IPv6, for UDP/TCP DNS and non-DNS traffic under competing NAT and LAN bypass. Positive controls prove observation, kernel traces attribute the drop, and removing the dedicated rule proves the checks detect its absence. Separate cases cover normal local DNS redirection and the disabled-IPv6 killswitch. Tor and DNS resolution themselves are not exercised by these firewall tests.

    Documentation

    • Record the 0.5.0 qualification status: ROADMAP lists the defects found and fixed during qualification (#132, #149, #150, #152, #154) and what release validation still requires, including ParrotOS re-qualification of the final candidate; ADR 0015 and the README no longer describe VM gates as pending.
    • Document the approved DNSSEC policy, manual resolution of explicit interface conflicts and the internal systemd state-format compatibility dependency.
    • Separate completed, approved and undecided 0.5.0 roadmap work, with indicative implementation estimates rather than a committed release date.
    • Add a staged diagnostic procedure for hardened hosts, including Quad9, existing firewalls, local DNS proxies, browser DoH, Tor bootstrap and probe failures. Collect evidence before teardown or configuration changes.

    [0.4.11] - 2026-10-06

    A security fix, and less root in what TTP runs. --bridge-file let a caller allowed to run sudo ttp and nothing else read root-only files; it now reads the file with the caller's own permissions. Tor is no longer started as root, both units TTP starts are sandboxed, and the answers TTP fetches from the network to check that it is using Tor are parsed by nobody instead of root.

    Upgrade if a sudoers rule grants ttp to anyone who is not otherwise root (GHSA-wc5v-93m5-3vc6). On Fedora, the SELinux module is updated at the next ttp start.

    Security

    • --bridge-file no longer lets sudo ttp read files its caller cannot (GHSA-wc5v-93m5-3vc6, 0.4.5-0.4.10). ttp start runs as root and opened the file as root. A rejected line was printed verbatim in the error, and any line whose first token merely contained : - every line of /etc/shadow - was accepted as a bridge and written into the torrc. Where sudo is granted for ttp alone, that read root-only files. Under sudo or pkexec the file is now read by a child running as the caller, with the caller's groups, so the kernel applies the caller's permissions and root never opens the path; a bridge address must be an IP and a port, as Tor requires; and errors name the line number, never its content. Verified in a container: as root with SUDO_UID set, a root-only file is refused (Permission denied) and the caller's own file is read.

    Changed

    • Untrusted network input is handled by an unprivileged process. ttp start and ttp check verify Tor by fetching JSON from check.torproject.org and two IP echo services; as root, the TLS, HTTP and JSON parsing of that third-party data ran in the root process. It now runs in a child as nobody (ttp/netprobe.py, standard library only), which hands back at most four fields - the three address keys and IsTor - reduced to their types and bounded lengths, and root validates them again. nobody rather than the invoking user because it is never in a bypass list, so the probe always goes through Tor. If the child cannot run, as for an install under a home directory, the check falls back to the old behaviour and logs why. Verified in a container as root: the child runs as uid/gid 65534 with no supplementary groups, and a real fetch through it returns the reduced answer.
    • Tor is never started as root. The distributions' units start Tor as root and let it drop to its account through the torrc's User directive, keeping CAP_SETUID/CAP_SETGID and CAP_NET_BIND_SERVICE for low ports. TTP's ports are above 1024, so ttp-tor.service now starts Tor as its account (User=) with no capabilities at all, and the torrc no longer carries User. Only the ExecStartPre=+ lines that prepare Tor's directories run as root.
    • Both units TTP starts are sandboxed. ttp-tor.service: ProtectSystem=strict with writes only to its cache and runtime directories, PrivateDevices, PrivateTmp, ProtectHome, kernel and cgroup protections, MemoryDenyWriteExecute, and sockets limited to UNIX, INET, INET6 and NETLINK. ttp-watchdog.service: ProtectSystem=strict with writes only to /run/ttp/watchdog, sockets limited to UNIX and NETLINK (it never opens a network socket), and the same kernel protections. systemd-analyze security exposure: ttp-tor 9.6 (UNSAFE) -> 3.2 (OK); ttp-watchdog 6.6 (MEDIUM) -> 3.4 (OK). systemd-analyze verify accepts every directive (tested).
    • The SELinux module allows the Tor domain transition under NoNewPrivileges (ttp_tor_policy 1.3). SELinux refuses a domain transition for a process with no_new_privs unless it is allowed explicitly, so on Fedora the sandboxed unit started Tor in init_t rather than tor_t, and Tor died on its own lock file (Couldn't open .../lock for locking: Permission denied). Found by the Fedora lifecycle VM; the module now carries allow init_t tor_t:process2 nnp_transition, and hosts pick it up through the existing version stamp.

    Fixed

    • Dependabot no longer raises the oldest-supported pins. It treated packaging/oldest-supported.txt as a requirements file to keep current and opened PRs moving typer, click, rich and transitions to their newest releases; one (six 1.16.0 -> 1.17.0) was merged. That file is what the "oldest supported dependencies" CI job installs, so the PRs would have made it test the newest versions instead. It is now packaging/oldest-supported.pins, which Dependabot does not read, six is back at Ubuntu 24.04's 1.16.0, and a test fails if either regresses.

    • The chaos sweep refuses to run without a running watchdog. A watchdog that fails to start only makes ttp start --watchdog print an error; the sweep then ran with no watchdog and reported the first fault only the watchdog can contain as a leak. It now requires ttp-watchdog.service to be active, and still active 3 s later, before injecting anything. (The watchdog had failed with 226/NAMESPACE: its new ReadWritePaths named a directory that exists only with the ttp-watchdog account. The entry is now optional.)

    • The documentation no longer says wall reaches terminals. 0.4.10 said only wall reached anyone. It does not, from the ttp-watchdog account: terminals are 0620 <user>:tty, the account is not in tty, wall is not setgid on Debian 13, and NoNewPrivileges would void it where it is. The killswitch itself is unaffected.

    [0.4.10] - 2026-09-30

    A release of the release process. Nothing a running session does has changed; what changed is what a published TTP can be checked against. It is the first release built to be reproducible: right after it is published, CI rebuilds it from its tag on a separate runner and compares the result, byte for byte, with what was published. Every asset is signed and verified from what was published, the build environment is pinned by hash, each package has its own SBOM, and the unit suite now covers 99.9% of ttp/.

    Nothing to do before upgrading. Two things to know:

    • Desktop notifications do not arrive, and never have. The watchdog calls notify-send from a system service that has no user's session bus. Only wall reaches anyone, in terminals. The docs said otherwise; they no longer do. Real desktop notifications are a v0.5.0 item.
    • The single sbom.json is replaced by one <artifact>.cdx.json per package.

    Added

    • Every release is verified from what was published. scripts/verify-release.sh <tag> downloads a release and fails unless every asset verifies against its Sigstore bundle with a certificate naming this repository's release.yml at that tag, SHA256SUMS.txt matches, and PyPI serves exactly the signed wheel and sdist. .github/workflows/verify-release.yml runs it after every release, weekly on the latest release (an asset replaced later fails there) and on demand, then installs the published .deb and .rpm in clean containers.
    • Reproducible builds. Two builds of the same commit are now identical byte for byte - wheel, sdist, .deb, .rpm, SBOMs and SHA256SUMS.txt. Every timestamp is the commit's (SOURCE_DATE_EPOCH), the .deb's files are normalised, and the .rpm records no build host and is built in a Fedora 44 image pinned by digest. The wheel and sdist are built from a copy of the sources with normalised permissions, in a Python image pinned by digest: the same files compress to different bytes under Fedora's zlib-ng, so a wheel built on a Fedora host never matched one built on Ubuntu. Measured: the wheel, the sdist and the .rpm built on a Fedora workstation are byte-identical to CI's (the .deb depends on the host's dpkg-deb). scripts/check-reproducible.sh builds twice from two copies of the tree and compares; a new CI job runs it on every change, and verify-release.yml rebuilds each release from its tag and compares it with what was published. docs/verification.md explains how to rebuild a release yourself, and the limits.
    • One SBOM per artifact. <artifact>.cdx.json for the wheel, sdist, .deb and .rpm, read from the artifact by packaging/make_sbom.py: the artifact by version and SHA-256, what it contains besides TTP (the .rpm's bundled transitions), and what it requires, with the floor and who provides it. Each is validated against the official CycloneDX schema before signing.

    Changed

    • Test coverage of ttp/ is 99.9%, and the ratchet is 99% (was 96%). The new tests are the branches that run when something has already gone wrong: a killswitch that fails to apply, teardown with no usable Tor UID, an unreadable firewall listing, a control socket that refuses TTP, a crashed watchdog loop, a resolver file swapped or hard-linked between being written and being used, a binary in a directory someone other than root can write. None of them had ever been executed by a test. The four lines left are the CLI's __main__ guard and the fallback for a missing stem, a hard dependency.
    • The release build environment is pinned by version and hash. packaging/build_python.sh installs packaging/build-requirements.txt - the build frontend, hatchling and their dependencies, each at one version and one SHA-256 - with --require-hashes into a throwaway venv and builds from it; the wheel, the sdist and the wheels inside the .deb and .rpm all go through it. pyproject.toml keeps its hatchling>=1.27 floor for downstream packagers. packaging/pin_build_backend.py regenerates the file.
    • The single sbom.json is gone. It was made by cdxgen from the checkout and described the CI runner's Python environment (rich 15.0.0, typer 0.27.2), not any artifact; cdxgen was also installed unpinned with npm install -g in the job holding the signing token.

    Fixed

    • The documentation no longer promises desktop notifications. docs/architecture.md, the watchdog page and ROADMAP.md said the killswitch was announced with notify-send; it is called, but from a system service with no session bus, so no desktop shows it.
    • A dead branch in check_tmpfs_space is gone. It re-raised StateError from an except OSError that StateError can never reach; found because no test could execute it.

    • The sdist contains only what it is meant to. Its include patterns were unanchored gitignore patterns, so "README.md" and "assets" also matched docs/decisions/README.md and docs/web/assets/mark.svg, which 0.4.9's sdist shipped, and "LICENSE" would match any LICENSE file under the build directory. Found by the reproducibility check, whose two builds disagreed.

    • The generated ruleset no longer says Ellipsis. A comment in the filter_out template wrote {...} inside an f-string, so the ruleset an operator reads with nft list table inet ttp said ip daddr Ellipsis. A test now fails if any Python value leaks into the rendered ruleset.

    • The test suite passes with FORCE_COLOR set. Rich's consoles are built when ttp is imported and read FORCE_COLOR (and TTY_COMPATIBLE) then, so 11 CLI tests saw ANSI escapes in the text they assert on. tests/conftest.py clears both before the first import, and a test runs a CLI test in a child pytest with each set.

    [0.4.9] - 2026-09-29

    The result of TTP's first end-to-end security audit, and of the verification work it set off. The audit's findings are under Security: every one survived independent verification, and the full report, including the seven candidates that were disproved and the work still open, is at docs/security/audit-2026-09.md. Checking those fixes on real hosts then found leaks and watchdog failures that no unit test had reached. They are under Fixed, and the VM, chaos and competing-ruleset suites that found them are under Added.

    Two things to know before upgrading:

    • ttp start and ttp restart now exit 3, not 0, when Tor cannot be verified. Scripts that chain on their exit code should be checked; see Changed.
    • A session does not survive a reboot. This is not new, but it is now measured and documented: after a reboot the host is in cleartext until ttp start is run again. See section 4.3 of docs/security-assessment.md.

    Security

    • /run/ttp is no longer handed to the ttp-watchdog account. It stays root-owned; the watchdog gets group read and its own subdirectory. Owning the directory let that account replace root's lock, log, resolv.conf or ruleset with a symlink and redirect a root-privileged write. This also unblocks the watchdog, which previously could not read the lock it was monitoring.
    • A lock tor_uid can no longer become an extra nft command. nft joins its arguments into one buffer and lexes it line-wise, so a newline in that value inserted an attacker-chosen rule at the top of filter_out during ttp stop — while the teardown was logged as successful.
    • The Tor account is identified by its binary, not by a process name. A ps row is trusted only when /proc/<pid>/exe is the resolved tor binary, BYOD account names are matched exactly rather than by substring, and a non-system account is refused outright.
    • The IPv6 kill-switch now precedes every cleartext exemption. With --no-ipv6, --allow-root, --bypass-user/--bypass-group and ttp bypass previously leaked that principal's IPv6 to the WAN.
    • A --bridge value must be a single line. A newline in one injected arbitrary directives into the generated torrc.
    • The nftables ruleset is piped to nft on stdin, and the volatile resolv.conf and log file are opened with O_NOFOLLOW and validated, so no fixed name in /run/ttp is resolved twice or followed.
    • ttp bypass resets the supplementary group vector. systemd-run --scope never calls initgroups(), so --uid/--gid alone left root's groups — gid 0 at minimum — on the bypassed process. It is now wrapped in setpriv --init-groups.
    • Only check.torproject.org may assert IsTor, and reflector values are canonicalised through ipaddress before being displayed, so a reflector can no longer flip the verification verdict, abort a command mid-output, or repaint the terminal.
    • The PID-recycling guard matches argv tokens, not a substring. "http" contains "ttp", so any curl, wget or httpd process defeated it.
    • Every GitHub Action is pinned to a commit SHA. All 40 uses: references were on mutable tags, including the Sigstore signing and PyPI publishing steps in jobs holding id-token: write.

    • The watchdog now actually receives nftables events (#81).     • A connection open before ttp start is reset instead of left hanging (#36). Nothing escaped on such a connection, but the application was never told: the error the kernel generates for a rejected local packet is addressed to the host's own address, and on a public address filter_out's catch-all rejected that error too, so a sender and a receive-only client both hung until their own timeout. filter_out now accepts traffic to the host's own addresses (fib daddr type local, placed after the IPv6 kill-switch and the un-redirected DNS guard so neither is shadowed), and the catch-all answers TCP with a reset, which an established receive-only socket acts on where it ignores ICMP. No rule is inserted and removed around ttp start, so there is nothing to clean up and no exemption list to keep in step: it is the rule that already applies the exemptions. cleartext_rejected no longer counts TTP's own error replies, so ttp status reports fewer blocked packets for the same traffic. docs/security-assessment.md said the reset was sent immediately, which was not true before this change.

    • A foreign nat chain ahead of TTP's could carry DNS to a LAN resolver in cleartext (#29). The kernel accepts nat base chains down to priority -199, below TTP's nat output at -150, and the first nat chain to bind a connection ends NAT evaluation for it. A chain there that DNATed port 53 therefore pre-empted TTP's DNS redirect entirely. Rewritten to a WAN resolver the query died at the catch-all reject; rewritten to a LAN resolver it was accepted by filter_out's LAN bypass and left the host, over UDP and TCP, with no TTP counter moving. Reproduced without root in a user network namespace against the generated ruleset. filter_out now rejects, ahead of the LAN bypass, any original-direction packet whose conntrack original destination port was 53 and which is not headed for loopback; it carries the dns_unredirected_rejected counter, which the watchdog treats as an integrity failure alongside doh_rejected and dot_rejected. Traffic TTP already handled is unchanged: its own redirect rewrites the destination to loopback first. docs/security-assessment.md 3.1 claimed this case was detected by the DoH/DoT counters, which never see port 53; it now describes the reject. The accept-only competitors #29 was first tested with remain as they were: accept is chain-scoped and does not bypass TTP.

It resolved a single STUN hostname, and under a live session that resolution goes through Tor's DNSPort — so it depends on whichever exit Tor happened to pick. One exit returned no AAAA for stun.l.google.com, the probe reported INCONCLUSIVE, and the build failed for a reason with nothing to do with whether UDP is contained. The probe now walks a list of public STUN servers and uses the first that resolves, reporting UNREACHABLE only when none of them does, and naming each one it tried. The target still has to be a real STUN server — this probe detects a leak by receiving a reply, so pointing it at an arbitrary routable address would turn it into a test that cannot fail.

    • A leak probe that could not send looked identical to a firewall that blocked it. But the positive control runs the same script with the ruleset flushed, where a refused send is the instrument failing to produce the traffic whose absence is about to be asserted. Browsers that cache the LAN gateway (e.g. 192.168.1.1:53) as their DNS resolver would have their queries accepted by the LAN bypass and sent directly to the ISP resolver - bypassing Tor entirely. The DNS redirect rule now runs before the LAN bypass in both the output and prerouting chains. Discovered via manual leak testing on browserleaks.com/dns.
    • Watchdog: Passive Tor Health Check (False Negative) (watchdog.py): check_system_integrity() was verifying Tor health via ctrl.close(), a local Python object operation that succeeds even when the Tor daemon has crashed and only a stale socket file remains. Replaced with ctrl.get_info("status/bootstrap-phase"), an active round-trip query that correctly raises an exception on a dead or stale socket.
    • Watchdog: Ignored Auto-Healing Return Value (Killswitch Delay) (watchdog.py): run_watchdog_loop() ignored the return value of attempt_auto_healing(). If the healing command itself failed (e.g. nft unable to re-apply rules), the loop would still wait 3 seconds, re-run the integrity check, detect the same failure, and only then activate the killswitch - creating a window where traffic could flow in cleartext. The emergency killswitch is now triggered immediately if attempt_auto_healing() returns False.
    • SELinux Module Version Inconsistency (scripts/install.sh): The shell installer checked for the presence of the ttp_tor_policy module without verifying its version. If v1.0 was installed, the script would skip reinstallation while Python's tor_detect.py would still report the module as outdated (requiring v1.1). The check is now grep -qE "ttp_tor_policy[[:space:]]+1\.1", consistent with the Python detection logic.
